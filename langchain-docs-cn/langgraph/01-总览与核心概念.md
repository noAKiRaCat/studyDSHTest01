# LangGraph 01 · 总览与核心概念

> LangGraph 是一个**低层编排框架**：它不替你决定流程，只提供「状态 + 节点 + 边」这套积木，让你精确控制每一步。

---

## 1. 它解决什么问题

传统 Agent 框架的问题是「黑盒循环」：你只知道输入输出，中间怎么走的不可控。

LangGraph 的答案是：**把 Agent 画成一张状态图**。

```text
[入口] → [分类节点] → 条件边 ─┬─→ [检索节点] → [生成节点] → [结束]
                              └─→ [直接回答] ──────────────→ [结束]
```

好处：

1. **确定性步骤与模型步骤混排**：该确定的地方写死代码，该灵活的地方交给模型。
2. **可持久化**：每一步都存快照，崩了能续跑。
3. **可中断**：任意节点前暂停，等人审批。
4. **可回溯**：回到历史状态，改一条分支重跑。

## 2. 安装与最小示例

```bash
pip install -U langgraph
```

```python
from langgraph.graph import StateGraph, MessagesState, START, END

def mock_llm(state: MessagesState):
    return {"messages": [{"role": "ai", "content": "hello world"}]}

builder = StateGraph(MessagesState)
builder.add_node("model", mock_llm)
builder.add_edge(START, "model")
builder.add_edge("model", END)

graph = builder.compile()
graph.invoke({"messages": [{"role": "user", "content": "hi!"}]})
```

## 3. 四个核心概念

### 3.1 State（状态）

图共享的数据结构，是一个 TypedDict：

```python
from typing import Annotated
import operator
from typing_extensions import TypedDict


class State(TypedDict):
    messages: Annotated[list, operator.add]   # 追加而非覆盖
    step_count: int                            # 覆盖
```

**Reducer（归约器）** 决定「节点返回的值如何合并进状态」：

| 写法 | 语义 |
|---|---|
| 无注解 | 覆盖 |
| `Annotated[list, operator.add]` | 拼接 |
| `Annotated[int, operator.add]` | 相加 |
| 自定义函数 | 任意合并逻辑 |

### 3.2 Node（节点）

一个函数（或 Runnable），接收 state，返回**要更新的字段**：

```python
def call_model(state: State):
    response = model.invoke(state["messages"])
    return {"messages": [response], "step_count": state["step_count"] + 1}
```

节点可以是：同步函数、异步函数、LangChain Runnable、另一个编译好的图（子图）。

### 3.3 Edge（边）

- **普通边**：`add_edge("a", "b")`，走完 a 必走 b。
- **条件边**：`add_conditional_edges("a", router, mapping)`，按 router 的返回值跳转。
- **入口/出口**：`START` / `END` 是特殊常量。

```python
def router(state: State) -> str:
    return "tools" if state["messages"][-1].tool_calls else END

builder.add_conditional_edges("agent", router, {"tools": "tools", END: END})
```

### 3.4 Compile（编译）

```python
graph = builder.compile(checkpointer=checkpointer)
```

编译时可以做：绑定检查点、指定中断点、校验图结构。

## 4. 两套 API

### 4.1 Graph API（显式图）

适合：流程清晰、需要可视化、需要多节点协作。

```python
builder = StateGraph(State)
builder.add_node("a", node_a)
builder.add_node("b", node_b)
builder.add_edge(START, "a")
builder.add_conditional_edges("a", router)
graph = builder.compile()
```

### 4.2 Functional API（函数式）

适合：流程简单线性、不想画图、想把现有代码快速接上持久化与中断。

```python
from langgraph.func import entrypoint, task

@task
def call_model(messages):
    return model.invoke(messages)

@entrypoint(checkpointer=checkpointer)
def workflow(messages: list):
    response = call_model(messages).result()
    return response
```

**怎么选**：

| 维度 | Graph API | Functional API |
|---|---|---|
| 可读性 | 流程复杂时更清晰 | 线性流程更简洁 |
| 可视化 | 原生支持 | 弱 |
| 复用 | 可做子图 | 适合封装工具函数 |
| 学习成本 | 中 | 低 |

> 官方建议：**先用 Functional API 快速验证，流程复杂后迁移到 Graph API**。两者可以混用（函数式流程里调用编译好的图）。

## 5. LangGraph 提供的「硬能力」

这些是你自己写循环很难做好的：

### 5.1 持久化（Persistence）

```python
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "t-1"}}
graph.invoke({"messages": [...]}, config)
```

每一步执行后自动存档，进程重启可续跑。

### 5.2 中断（Interrupts）

```python
from langgraph.types import interrupt

def approve_node(state):
    decision = interrupt({"action": "delete_file", "path": state["path"]})
    ...
```

执行到这里暂停，外部用 `Command(resume=...)` 继续。

### 5.3 流式（Streaming）

```python
for chunk in graph.stream(inputs, stream_mode="updates"):
    print(chunk)
```

### 5.4 容错（Fault Tolerance）

节点级重试、超时、错误处理：

```python
builder.add_node(
    "call_api",
    call_api,
    retry_policy={"max_attempts": 3, "initial_interval": 0.5},
)
```

### 5.5 时间旅行

```python
history = list(graph.get_state_history(config))
graph.invoke(None, {"configurable": {"thread_id": "t-1", "checkpoint_id": history[2].config["configurable"]["checkpoint_id"]}})
```

## 6. 与 LangChain 的关系

```text
LangGraph  ← 独立可用，不需要 LangChain
   ↑
LangChain create_agent 编译出来的就是一个 LangGraph 图
   ↑
Deep Agents 在 LangChain 之上再叠一层中间件
```

所以在 LangGraph 里你可以直接用 LangChain 的模型与工具，也可以完全不用它：

```python
# 不用 LangChain 的写法
def call_model(state):
    resp = openai_client.chat.completions.create(...)
    return {"messages": [{"role": "ai", "content": resp.choices[0].message.content}]}
```

## 7. 一个完整的 ReAct 图

```python
from typing import Annotated
import operator
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode


class AgentState(TypedDict):
    messages: Annotated[list, operator.add]


def agent_node(state: AgentState):
    return {"messages": [model_with_tools.invoke(state["messages"])]}


def should_continue(state: AgentState) -> str:
    last = state["messages"][-1]
    return "tools" if getattr(last, "tool_calls", None) else END


builder = StateGraph(AgentState)
builder.add_node("agent", agent_node)
builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue, {"tools": "tools", END: END})
builder.add_edge("tools", "agent")

graph = builder.compile(checkpointer=InMemorySaver())
```

## 8. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 状态字段被覆盖 | 忘了加 reducer | `Annotated[list, operator.add]` |
| 图死循环 | 条件边永远返回节点名 | 加最大步数 `recursion_limit` |
| 中断后无法恢复 | 没传 `thread_id` | 中断必须有 checkpointer + thread |
| 节点返回非法值 | 返回了不在 State 里的键 | 严格按 schema 返回 |
