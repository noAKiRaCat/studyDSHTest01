# LangGraph 03 · 持久化与中断

> 持久化让 Agent 能「记住并续跑」，中断让它能「停下来等人」。这两件事是 LangGraph 最有价值的部分。

---

## 1. 持久化：Checkpointer

### 1.1 它存什么

每一步执行完，LangGraph 会保存一份**检查点（checkpoint）**：

```text
thread_id: t-1
├── checkpoint 0: 输入状态
├── checkpoint 1: search 执行后
├── checkpoint 2: write 执行后
└── checkpoint 3: review 执行后（当前）
```

包含：状态值、下一步该执行谁、已产生的写入、元数据。

### 1.2 启用

```python
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "conv-001"}}
graph.invoke({"messages": [...]}, config)
```

**没有 `thread_id` 就没有持久化**——这是最常见的疏漏。

### 1.3 生产级实现

| 实现 | 包 | 说明 |
|---|---|---|
| `InMemorySaver` | 内置 | 进程内存，重启即失 |
| `SqliteSaver` | `langgraph-checkpoint-sqlite` | 单文件，适合单机 |
| `PostgresSaver` | `langgraph-checkpoint-postgres` | 多实例、事务安全 |

```python
from langgraph.checkpoint.postgres import PostgresSaver

with PostgresSaver.from_conn_string(os.environ["PG_DSN"]) as saver:
    saver.setup()
    graph = builder.compile(checkpointer=saver)
```

### 1.4 Thread 与命名空间

```text
thread_id     一次会话（一个用户的一段对话）
checkpoint_id 该会话中的某个时刻
namespace     子图的隔离空间（自动派生）
```

同一 `thread_id` 的多次 `invoke` 会**追加**到同一条历史。

## 2. 读取与回溯

```python
# 当前状态
state = graph.get_state(config)
print(state.values)   # 状态字段
print(state.next)     # 下一个要执行的节点

# 全部历史（新→旧）
for snap in graph.get_state_history(config):
    print(snap.config["configurable"]["checkpoint_id"], snap.next)
```

**时间旅行**：

```python
history = list(graph.get_state_history(config))
target = history[2]                       # 回到第 3 个检查点之前

graph.invoke(None, {"configurable": {
    "thread_id": "conv-001",
    "checkpoint_id": target.config["configurable"]["checkpoint_id"],
}})
```

从该点重新执行，会产生一条**新分支**，原历史保留。

**典型用途**：用户说「刚才那版不好，重新来」——回到某个检查点重跑。

## 3. 中断（Interrupt）：人机协同

### 3.1 静态中断（编译时指定）

```python
graph = builder.compile(
    checkpointer=InMemorySaver(),
    interrupt_before=["delete_node"],   # 执行前暂停
    interrupt_after=["send_email"],     # 执行后暂停
)
```

### 3.2 动态中断（节点内调用）

```python
from langgraph.types import interrupt, Command


def approve_delete(state):
    decision = interrupt({
        "question": "确认删除这些文件吗？",
        "files": state["files"],
    })
    if decision.get("approved"):
        return {"status": "deleted"}
    return {"status": "cancelled"}
```

执行到 `interrupt()` 时图暂停，`invoke` 返回一个包含 `__interrupt__` 的结果。

### 3.3 恢复执行

```python
# 第一次调用：会停在中断处
result = graph.invoke({"files": [...]}, config)
print(result["__interrupt__"])

# 人工确认后恢复
graph.invoke(Command(resume={"approved": True}), config)
```

`Command(resume=...)` 的返回值会成为 `interrupt()` 的返回值。

### 3.4 多个中断与编辑状态

```python
# 恢复时同时修改状态
graph.invoke(
    Command(resume={"approved": True}, update={"reviewer": "alice"}),
    config,
)
```

### 3.5 Web 后端典型流程

```text
1. POST /run           → 返回 {status: "interrupted", payload: {...}}
2. 前端弹窗让用户确认
3. POST /resume        → graph.invoke(Command(resume=...), config)
4. 返回最终结果
```

**注意**：中断必须有 checkpointer，否则无法恢复。

## 4. 长期记忆：Store

Checkpointer 管**单次会话**，Store 管**跨会话**。

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
graph = builder.compile(checkpointer=saver, store=store)
```

### 4.1 基本读写

```python
namespace = ("user", "u-42")

store.put(namespace, "language", {"value": "中文"})
item = store.get(namespace, "language")
print(item.value)          # {"value": "中文"}

store.delete(namespace, "language")
store.list(namespace)      # 列出该命名空间所有条目
```

### 4.2 语义检索

```python
from langchain_openai import OpenAIEmbeddings

store = InMemoryStore(index={"embed": OpenAIEmbeddings(), "dims": 1536})

store.put(("mem", "u1"), "m1", {"text": "用户偏好简洁回答"})
store.put(("mem", "u1"), "m2", {"text": "用户是后端工程师"})

hits = store.search(("mem", "u1"), query="技术背景", limit=3)
for h in hits:
    print(h.value["text"], h.score)
```

### 4.3 在节点里使用

```python
def recall(state, config, *, store):
    ns = ("mem", config["configurable"]["user_id"])
    hits = store.search(ns, query=state["question"], limit=5)
    return {"memories": [h.value["text"] for h in hits]}
```

> 节点函数签名支持注入 `config`、`store`、`runtime` 等，具体取决于版本，建议以官方 API 参考为准。

## 5. 持久化 + 中断的组合模式

### 模式 A：长任务断点续跑

```text
任务被中断（进程重启 / 用户离开）
  → 下次 invoke 同一 thread_id
  → 从最后一个检查点继续，不重复执行已完成节点
```

前提：**节点必须幂等**，或把副作用放在检查点之后。

### 模式 B：多轮审批

```python
def step1(state):
    return {"plan": make_plan(state)}

def human_review(state):
    ok = interrupt({"plan": state["plan"]})
    return {"approved": ok}

def step2(state):
    if not state["approved"]:
        return {"status": "rejected"}
    return {"result": execute(state["plan"])}
```

## 6. 性能与容量

| 关注点 | 建议 |
|---|---|
| 检查点数量 | 设置保留策略，定期归档旧 thread |
| 状态体积 | 不要把大文件塞进 state，用 Store 或外部存储 |
| 写入频率 | Postgres 用连接池；高并发注意事务隔离 |
| 序列化 | 自定义对象需实现可序列化（或用 dict） |

---

## 7. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `invoke` 无法续跑 | 没传 `thread_id` 或换了 ID | 前端持久化会话 ID |
| 恢复后重复执行 | 节点不幂等 | 把副作用做成幂等，或放在审批后 |
| `interrupt` 报错 | 未配置 checkpointer | 必须一起用 |
| 状态里出现巨大对象 | 把二进制塞进 state | 存引用（路径/ID），内容放外部 |
| 历史查询很慢 | thread 太长 | 分页 + 定期归档 |
