# LangChain 02 · 模型与消息

> 模型是 Agent 的「推理引擎」，消息是模型的「输入输出格式」。这一篇解决：怎么统一接入各家模型、消息长什么样、多模态怎么传。

---

## 1. 初始化模型

### 1.1 字符串快捷方式

```python
from langchain.agents import create_agent

agent = create_agent(model="openai:gpt-5.5", tools=[])
```

格式固定为 `"provider:model_name"`。

### 1.2 `init_chat_model`（推荐）

需要参数控制时用它：

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "openai:gpt-5.5",
    temperature=0.3,
    max_tokens=2048,
    timeout=60,
    max_retries=2,
)
```

### 1.3 直接实例化

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="gpt-5.5",
    base_url="https://api.example.com/v1",   # 兼容 OpenAI 协议的第三方网关
    api_key="sk-...",
    temperature=0,
)
```

---

## 2. 常用参数

| 参数 | 作用 | 备注 |
|---|---|---|
| `temperature` | 随机性，0~2 | 事实类任务用 0~0.3 |
| `max_tokens` | 输出上限 | 影响成本与截断 |
| `timeout` | 单次请求超时（秒） | 长任务要调大 |
| `max_retries` | 失败重试次数 | 配合限流使用 |
| `base_url` | 自定义网关 | 代理/私有部署 |
| `streaming` | 是否流式 | 交互式应用建议开 |

## 3. 消息类型

LangChain 用统一的消息对象表达对话：

```python
from langchain.messages import (
    SystemMessage,   # 系统提示
    HumanMessage,    # 用户输入
    AIMessage,       # 模型输出（可能带 tool_calls）
    ToolMessage,     # 工具执行结果
)
```

### 3.1 用字典构造（最简）

```python
messages = [
    {"role": "system", "content": "你是一个严谨的助手"},
    {"role": "user", "content": "解释一下 CAP 定理"},
]
```

### 3.2 用对象构造（可控性更强）

```python
from langchain.messages import SystemMessage, HumanMessage

messages = [
    SystemMessage("你是一个严谨的助手"),
    HumanMessage("解释一下 CAP 定理"),
]
```

两种形式可以混用，最终都会被规范化为消息对象。

## 4. 消息字段详解

### 4.1 `AIMessage`

```python
response = model.invoke("你好")

response.content          # 文本内容（可能为空，比如只调工具时）
response.content_blocks   # 结构化内容块（文本、图片、思考过程等）
response.tool_calls       # 模型请求调用的工具列表
response.usage_metadata   # token 用量
response.response_metadata # 供应商原始元信息
```

**为什么要用 `content_blocks`**：不同供应商返回的结构差异大（Anthropic 的 thinking 块、OpenAI 的 reasoning 摘要、Gemini 的多模态块），`content_blocks` 提供统一视图。

```python
for block in response.content_blocks:
    print(block["type"], block)
```

### 4.2 `ToolMessage`

工具执行完必须回传，并带上 `tool_call_id` 与调用请求对应：

```python
ToolMessage(
    content="北京今天晴，25℃",
    tool_call_id="call_abc123",
    name="get_weather",
)
```

> 漏掉 `tool_call_id` 是新手最常见的报错来源：模型会认为「有调用没结果」，进而重复调用。

### 4.3 消息的追加语义

Agent 的 `messages` 状态是**只追加**的：新消息只加不覆盖。

```python
state["messages"]        # 完整历史
state["messages"][-1]    # 最后一条
```

## 5. 多模态输入

不同供应商支持的能力不同，但 LangChain 用统一格式表达：

### 5.1 图片（URL）

```python
from langchain.messages import HumanMessage

msg = HumanMessage(
    content=[
        {"type": "text", "text": "这张图里有什么？"},
        {"type": "image_url", "image_url": {"url": "https://example.com/cat.jpg"}},
    ]
)
```

### 5.2 图片（本地文件 → base64）

```python
import base64

with open("chart.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode()

msg = HumanMessage(
    content=[
        {"type": "text", "text": "分析这张图表的趋势"},
        {
            "type": "image_url",
            "image_url": {"url": f"data:image/png;base64,{b64}"},
        },
    ]
)
```

### 5.3 支持的模态

| 模态 | 支持条件 |
|---|---|
| 文本 | 所有模型 |
| 图片 | GPT-4o+、Claude 3+、Gemini 全系 |
| 音频 | Gemini、部分 GPT-4o 变体 |
| 视频 | Gemini |
| PDF/文档 | Claude、Gemini（部分需转图片） |

> 工具返回多模态内容同样可行：`ToolMessage` 的 `content` 也接受内容块列表。

## 6. 结构化输出

让模型返回**符合 schema** 的结果，而不是自由文本。

### 6.1 Pydantic（推荐）

```python
from pydantic import BaseModel, Field
from langchain.agents import create_agent


class WeatherReport(BaseModel):
    """天气报告。"""
    city: str = Field(description="城市名")
    temperature: float = Field(description="摄氏温度")
    condition: str = Field(description="天气状况，如晴、雨、雪")


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[],
    response_format=WeatherReport,
)

result = agent.invoke({"messages": [{"role": "user", "content": "北京今天天气"}]})
print(result["structured_response"])   # WeatherReport(city='北京', ...)
```

### 6.2 TypedDict / JSON Schema

```python
from typing_extensions import TypedDict, Annotated

class Answer(TypedDict):
    summary: Annotated[str, ..., "一句话总结"]
    confidence: Annotated[float, ..., "0~1 的置信度"]
```

### 6.3 三种模式

| `response_format` 值 | 行为 |
|---|---|
| `"provider"` | 用供应商原生结构化输出能力（快，兼容性取决于模型） |
| `"tool"` | 把 schema 伪装成一个工具调用（兼容性最好，慢一点） |
| Pydantic/TypedDict | 自动选择最佳策略 |

## 7. 动态选模型

按任务难度、成本、可用性在运行时切换：

```python
from langchain.chat_models import init_chat_model

cheap = init_chat_model("openai:gpt-5-mini")
strong = init_chat_model("anthropic:claude-sonnet-5")

def pick(task: str):
    return strong if "复杂" in task else cheap
```

更常见的做法是用**中间件**实现按条件切换（见 [05 中间件](<05-中间件.md>)）。

## 8. 兼容 OpenAI 协议的网关

很多国产模型/自建服务兼容 OpenAI 的 `/chat/completions`：

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="deepseek-chat",
    base_url="https://api.deepseek.com/v1",
    api_key="sk-...",
)
```

> 注意：函数调用（tool calling）的**具体格式**各家实现有差异，遇到工具调用异常时优先检查网关的兼容性。

---

## 9. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `tool_calls` 为空但模型说「我要调用」 | 模型不支持或未绑定工具 | 用 `bind_tools` 或 `create_agent` 传入 `tools` |
| 多模态报 `unsupported content type` | 模型不支持该模态 | 换成视觉模型或先转文本 |
| 内容为空但 `content_blocks` 有值 | 只有思考块/工具块 | 读取 `content_blocks` 而非 `content` |
| token 用得飞快 | 历史消息无限增长 | 启用摘要中间件（Deep Agents 默认带） |
