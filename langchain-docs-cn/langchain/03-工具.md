# LangChain 03 · 工具（Tools）

> 工具是 Agent 的「手」。模型只能输出文字，真正查数据库、调 API、跑代码，全靠工具。

---

## 1. 最小工具

```python
from langchain.tools import tool


@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气。

    Args:
        city: 城市名称，例如 "北京"。
    """
    return f"{city}：晴，25℃"
```

三要素：

1. **函数名** → 工具名（模型看到的就是它）。
2. **docstring** → 工具描述（**模型据此决定何时调用**，务必写清楚）。
3. **类型注解** → 生成参数 schema，模型据此构造参数。

---

## 2. 参数模式

### 2.1 基础类型

```python
@tool
def search(query: str, limit: int = 5) -> list[str]:
    """搜索网页。

    Args:
        query: 搜索关键词。
        limit: 返回结果数量，默认 5。
    """
    return [f"结果 {i} of {query}" for i in range(limit)]
```

### 2.2 Pydantic 模型（复杂参数）

```python
from pydantic import BaseModel, Field
from langchain.tools import tool


class OrderQuery(BaseModel):
    """订单查询条件。"""
    order_id: str = Field(description="订单号")
    include_items: bool = Field(default=False, description="是否包含商品明细")


@tool
def query_order(params: OrderQuery) -> dict:
    """按订单号查询订单详情。"""
    return {"order_id": params.order_id, "status": "已发货"}
```

### 2.3 枚举约束

```python
from typing import Literal

@tool
def set_language(lang: Literal["zh", "en", "ja"]) -> str:
    """切换助手语言。"""
    return f"已切换到 {lang}"
```

`Literal` 会转成 JSON Schema 的 `enum`，模型不会瞎猜。

## 3. 运行时上下文（Runtime）

需要访问用户 ID、配置、其他依赖时，用 `ToolRuntime`：

```python
from dataclasses import dataclass
from langchain.tools import tool, ToolRuntime


@dataclass
class Context:
    user_id: str
    db: object


@tool
def get_my_orders(runtime: ToolRuntime[Context]) -> list[dict]:
    """查询当前用户的所有订单。"""
    user_id = runtime.context.user_id
    db = runtime.context.db
    return db.query(user_id)


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_my_orders],
    context_schema=Context,
)

agent.invoke(
    {"messages": [{"role": "user", "content": "我的订单有哪些？"}]},
    context=Context(user_id="u_123", db=my_db),
)
```

> `runtime` 参数**不会暴露给模型**，它是框架注入的。

可用属性：

| 属性 | 用途 |
|---|---|
| `runtime.context` | 本次运行传入的上下文对象 |
| `runtime.state` | 当前 Agent 状态（消息、自定义字段） |
| `runtime.store` | 长期记忆存储 |
| `runtime.config` | 运行配置（`thread_id` 等） |
| `runtime.tool_call_id` | 本次调用的 ID |

## 4. 工具返回值

| 返回类型 | 处理方式 |
|---|---|
| `str` | 直接作为 `ToolMessage.content` |
| `dict` / `list` | 序列化为 JSON 字符串 |
| `ToolMessage` | 原样使用（可自定义 `artifact`） |
| 内容块列表 | 支持多模态（图片等） |

### 返回结构化内容

```python
@tool
def make_chart(data: list[float]) -> list[dict]:
    """生成图表并返回图片。"""
    return [
        {"type": "text", "text": "图表已生成"},
        {"type": "image_url", "image_url": {"url": "https://.../chart.png"}},
    ]
```

### 错误处理

```python
@tool
def divide(a: float, b: float) -> str:
    """执行除法 a / b。"""
    if b == 0:
        return "错误：除数不能为 0"      # 返回错误信息，模型可自行纠正
    return str(a / b)
```

> 工具抛异常会让整个 Agent 崩掉（除非配置了重试中间件）。**把可预期的失败变成文本返回**，让模型自己重试。

## 5. 动态工具

### 5.1 按用户权限过滤

```python
def build_agent(user_role: str):
    tools = [search_public]
    if user_role == "admin":
        tools += [delete_user, view_audit_log]
    return create_agent(model="openai:gpt-5.5", tools=tools)
```

### 5.2 按状态动态启用

```python
from langchain.agents.middleware import wrap_model_call
from langchain.agents.middleware.types import ModelRequest


@wrap_model_call
def conditional_tools(request: ModelRequest, handler):
    if request.state.get("verified"):
        return handler(request)
    # 未验证用户只给只读工具
    return handler(request.override(tools=[search_public]))
```

## 6. 并行工具调用

模型一次请求多个工具时，LangChain 会并行执行：

```python
result = agent.invoke({
    "messages": [{"role": "user", "content": "同时查北京和上海的天气"}]
})
# 模型返回两个 tool_calls，两个 get_weather 并行执行
```

要控制并发，在中间件里加信号量或使用 `ToolRetryMiddleware` 的并发配置。

## 7. 工具描述怎么写才好用

**差的描述**：

```python
@tool
def search(q: str) -> str:
    """搜索"""
```

模型不知道搜什么、返回什么、什么时候该用。

**好的描述**：

```python
@tool
def search_company_docs(query: str, top_k: int = 3) -> str:
    """在公司内部知识库中检索文档片段。

    适用场景：用户询问公司制度、产品手册、历史项目等内部资料时使用。
    不适用：通用常识或实时新闻。

    Args:
        query: 自然语言查询，尽量包含关键词。
        top_k: 返回片段数，1~10，默认 3。

    Returns:
        若干文档片段，每段以 [来源: 文件名] 开头。
    """
```

**四条经验**：

1. 写清**何时用 / 何时不用**。
2. 参数说清**格式与范围**。
3. 说明**返回结构**，便于模型解析。
4. 工具之间**职责不重叠**，否则模型会乱选。

## 8. MCP 工具

从 MCP 服务器加载工具（详见 LangChain MCP 章节）：

```python
from langchain.mcp import MCPAdapter

async with MCPAdapter("http://localhost:8000/mcp") as adapter:
    tools = await adapter.get_tools()
    agent = create_agent(model="openai:gpt-5.5", tools=tools)
```

## 9. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 模型从不调用工具 | 描述太笼统 | 补「适用场景」 |
| 参数类型错 | 缺类型注解 | 全部加注解 |
| 报 `tool_call_id mismatch` | 手动构造 ToolMessage 忘了 ID | 用框架自动回填 |
| 工具超时拖垮全局 | 同步阻塞调用 | 加 `timeout` + 中间件重试 |
| 重复调用同一工具 | 返回值里没有结论 | 返回明确的「已完成」信号 |
