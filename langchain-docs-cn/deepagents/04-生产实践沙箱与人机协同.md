# Deep Agents 04 · 生产实践、沙箱与人机协同

> 从「能跑」到「敢上线」，要补的是：隔离执行、人工闸门、故障韧性、可观测性。

---

## 1. 代码执行的两条路

| 方式 | 工具 | 能力 | 隔离 |
|---|---|---|---|
| 沙箱后端 | `execute` | shell、装包、跑测试、访问文件系统 | 容器/虚拟机级 |
| 解释器 | `eval` | JS（QuickJS）表达式、数据变换 | 进程内、无网络无文件 |

### 1.1 沙箱后端

当后端实现 `SandboxBackendProtocolV2` 时，harness 自动挂上 `execute` 工具。

```python
from deepagents import create_deep_agent
from deepagents.backends import SandboxBackend   # 示意

agent = create_deep_agent(
    model="openai:gpt-5.5",
    backend=SandboxBackend(provider="e2b", ttl=3600),
)
```

**能力**：

- 安装依赖（`pip install`）
- 运行测试与构建
- 调用 CLI 工具
- 真实文件系统读写

**注意**：权限规则（`permissions`）**不作用于沙箱后端**。要限制，请在沙箱镜像里做（只读挂载、网络策略、非 root 用户）。

### 1.2 解释器

适合：循环、批处理、确定性数据变换、程序化调用工具。

不适合：装包、访问网络、持久化。

```python
agent = create_deep_agent(
    model="openai:gpt-5.5",
    middleware=[InterpreterMiddleware()],   # 概念示意
)
```

**为什么需要它**：让模型写 5 行 JS 做过滤/聚合，比来回调 20 次工具便宜得多。

## 2. 人在环（Human-in-the-loop）

### 2.1 基本配置

```python
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="openai:gpt-5.5",
    interrupt_on={
        "edit_file": True,          # 每次编辑都暂停
        "execute": True,            # 每次命令执行都暂停
        "write_file": {"allow_accept": True, "allow_edit": True},
    },
)
```

`interrupt_on` 接受「工具名 → 配置」的映射；暂停后可以：**批准 / 修改参数 / 拒绝**。

### 2.2 恢复执行

与 LangGraph 的中断机制一致：

```python
agent.invoke(Command(resume={"type": "accept"}), config)
```

（具体形状以官方 API 为准：`accept` / `edit` / `response` 三类决定。）

### 2.3 用什么模式

| 场景 | 策略 |
|---|---|
| 只读分析 | 不开启中断 |
| 改代码 | `edit_file` / `write_file` 中断 |
| 跑命令 | `execute` 中断，且沙箱隔离 |
| 涉钱、涉删 | 一律中断 + 二次确认 |

### 2.4 设计原则

- **闸门放在副作用前**，不是之后。
- **给人类足够上下文**：暂停时应展示「要改哪个文件、改什么、为什么」。
- **避免疲劳**：只对危险操作暂停，别每步都问。

## 3. 容错（Fault Tolerance）

生产环境的真实故障：限流、超时、供应商抖动、网络闪断。

### 3.1 中间件组合

```python
from langchain.agents.middleware import (
    ModelRetryMiddleware,
    ToolRetryMiddleware,
    ModelFallbackMiddleware,
    ModelCallLimitMiddleware,
)

agent = create_deep_agent(
    model="anthropic:claude-sonnet-5",
    middleware=[
        ModelCallLimitMiddleware(max_calls=40),
        ModelFallbackMiddleware(fallback_models=["openai:gpt-5-mini"]),
        ModelRetryMiddleware(max_retries=3, initial_delay=1.0),
        ToolRetryMiddleware(max_retries=2),
    ],
)
```

### 3.2 幂等

重试 + 持久化要求副作用可重复。写文件用「覆盖」而非「追加」，调外部 API 带幂等键。

### 3.3 检查点

```python
from langgraph.checkpoint.postgres import PostgresSaver

agent = create_deep_agent(
    model="openai:gpt-5.5",
    checkpointer=PostgresSaver.from_conn_string(DSN),
)
```

配合 `thread_id`，长任务崩了能续。

### 3.4 超时

| 层次 | 手段 |
|---|---|
| 单次模型调用 | `timeout` 参数 + 重试 |
| 单次工具调用 | 工具内部超时 |
| 整个任务 | 外层看门狗 + `recursion_limit` |
| 沙箱 | TTL 自动回收 |

## 4. 可观测性

```bash
export LANGSMITH_TRACING=true
export LANGSMITH_API_KEY="lsv2_..."
```

在 LangSmith 中可以看到：

- 每次 `task` 调用派生了哪些子代理
- 每个文件读写操作
- 工具调用的输入输出与耗时
- 中断点与恢复点
- token 消耗分布（哪个子代理最贵）

**建议**：给关键路径加自定义事件（`get_stream_writer`），把业务里程碑也打进追踪。

## 5. 部署形态

```text
本机 / 容器            → python app.py（自托管 SDK）
LangSmith Deployment  → 托管运行时，自动扩缩容
Managed Deep Agents   → 连 harness 都托管，按目录结构配置
```

**自托管清单**：

- [ ] checkpointer 用 Postgres
- [ ] store 用 Postgres
- [ ] 沙箱有 TTL 与资源限额
- [ ] 网络出口有白名单
- [ ] 日志脱敏（API Key、用户数据）
- [ ] 成本告警（token/时长）
- [ ] 人机审批有通知渠道（邮件/Slack/IM）

## 6. 成本控制

| 手段 | 效果 |
|---|---|
| 子代理用小模型 | 大幅降低调研成本 |
| 提示缓存 | 系统提示不重复计费 |
| 上下文卸载 | 减少历史 token |
| 限制调用次数 | 防失控 |
| 结果缓存 | 重复查询不重复花钱 |
| 摘要压缩 | 长会话成本可控 |

**典型成本结构**：主代理（大模型）× 少量调用 + 子代理（小模型）× 多量调用。

---

## 7. 安全清单

```text
① 权限：permissions 限制读写路径，敏感文件 deny
② 沙箱：execute 只在隔离环境，非 root，禁外网（或白名单）
③ 审批：危险操作 interrupt_on
④ 审计：所有工具调用落日志
⑤ 注入：外部内容（网页/文件）视为不可信，别让模型直接执行指令
⑥ 密钥：不放系统提示，用环境变量或 vault
⑦ 输出：对外回复前做 PII / 机密信息扫描
```

## 8. 一个完整的生产配置

```python
from deepagents import create_deep_agent
from deepagents.backends import FilesystemBackend
from langchain.agents.middleware import (
    ModelRetryMiddleware,
    ToolRetryMiddleware,
    ModelFallbackMiddleware,
    ModelCallLimitMiddleware,
    SummarizationMiddleware,
)
from langgraph.checkpoint.postgres import PostgresSaver

backend = FilesystemBackend(root_dir="/srv/agent-workspace")

agent = create_deep_agent(
    model="anthropic:claude-sonnet-5",
    tools=[search, fetch_page, make_chart],
    system_prompt="你是资深分析师，先规划再执行，产出物写入 /out/。",
    backend=backend,
    memory=["/srv/agent-workspace/AGENTS.md"],
    permissions=[
        {"operations": ["read"], "paths": ["/srv/agent-workspace/**"], "mode": "allow"},
        {"operations": ["write"], "paths": ["/srv/agent-workspace/out/**"], "mode": "allow"},
        {"operations": ["write"], "paths": ["/srv/agent-workspace/**"], "mode": "deny"},
        {"operations": ["read", "write"], "paths": ["**/.env*"], "mode": "deny"},
    ],
    interrupt_on={"execute": True},
    subagents=[
        {
            "name": "researcher",
            "description": "网络调研，返回带出处的摘要",
            "system_prompt": "用 search/fetch_page 收集资料，输出要点+链接。",
            "tools": [search, fetch_page],
            "model": "openai:gpt-5-mini",
        }
    ],
    middleware=[
        ModelCallLimitMiddleware(max_calls=40),
        ModelFallbackMiddleware(fallback_models=["openai:gpt-5.5"]),
        ModelRetryMiddleware(max_retries=3),
        ToolRetryMiddleware(max_retries=2),
        SummarizationMiddleware(max_tokens=12000, keep_last=12),
    ],
    checkpointer=PostgresSaver.from_conn_string(DSN),
)
```

## 9. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 沙箱越权 | 权限规则不管 `execute` | 在镜像层做限制 |
| 审批形同虚设 | 只在最后一步中断 | 把闸门放在副作用前 |
| 重试放大故障 | 无上限重试 | 限制次数 + 熔断 |
| 成本失控 | 子代理递归派生 | 限制深度与次数 |
| 重启后任务丢失 | 内存 checkpointer | 换 Postgres |

到这里三家文档的主干都过完了。建议下一步：

1. 用 `create_agent` 做一个能跑的小工具（1 小时）
