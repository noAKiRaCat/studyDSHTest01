# 三者关系与选型：LangChain、LangGraph、Deep Agents

> 这是整个生态最容易搞混的地方。一句话版本：
> **LangGraph 是运行时，LangChain 是框架，Deep Agents 是成品骨架。**

---

## 1. 三层结构

```text
┌──────────────────────────────────────────────┐
│  Deep Agents（Agent 骨架 / Harness）           │  开箱即用
│  规划 · 虚拟文件系统 · 子代理 · 技能 · 记忆     │
├──────────────────────────────────────────────┤
│  LangChain（Agent 框架）                       │  create_agent
│  模型抽象 · 工具 · 中间件 · 结构化输出          │
├──────────────────────────────────────────────┤
│  LangGraph（编排运行时）                        │  最底层
│  状态图 · 持久化 · 中断 · 流式 · 容错           │
└──────────────────────────────────────────────┘
```

- **LangGraph** 不依赖 LangChain，可以单独使用。
- **LangChain 的 `create_agent`** 本质是「用 LangGraph 编译出来的一个预置图」。
- **Deep Agents** 在 `create_agent` 之上再叠一层中间件（文件系统、子代理、待办清单等）。

---

## 2. 各自解决什么问题

### LangGraph：我要完全掌控流程

适用：

- 流程里有**确定性步骤**（调一次内部 API、做一次规则校验）和**模型决策步骤**混排。
- 需要**断点续跑**：任务跑 30 分钟，进程挂了要能接着跑。
- 需要**人工审核**：执行敏感操作前暂停，等人批准。
- 需要**时间旅行**：回到某个状态重新走一条分支。

关键代价：你得自己定义状态、节点、边，代码量比 `create_agent` 大。

### LangChain：我要快速搭一个能用的 Agent

适用：

- 标准「模型 ↔ 工具」循环。
- 想用统一接口切换模型（OpenAI / Anthropic / Gemini / 本地 Ollama）。
- 需要现成的中间件：重试、限流、PII 脱敏、人在环、摘要压缩。

关键概念：

```text
Agent = Model + Harness
Harness = 提示词 + 工具 + 中间件
```

### Deep Agents：我要一个能干长活的 Agent

适用：

- 任务**跨很多步**，上下文会爆（研究、编码、数据分析）。
- 需要 Agent **自己读写文件**、维护 TODO、派子代理并行干活。
- 需要**技能包**按需加载、**长期记忆**跨会话保留。

Deep Agents = LangChain 的 Agent + 一整套默认中间件：

| 能力 | 来源 |
|---|---|
| 待办清单 `write_todos` | `TodoListMiddleware`（v0.7 起需显式开启） |
| 虚拟文件系统（ls/read/write/edit/glob/grep） | `FilesystemMiddleware` + Backend |
| 子代理 `task` | `SubAgentMiddleware` |
| 技能 / 记忆 / 摘要压缩 | 内置上下文管理 |

## 3. 选型决策树

```text
你要做什么？
│
├─ 只是想调模型、调工具，流程简单
│     └─▶ LangChain create_agent
│
├─ 流程复杂、要精确控制每一步、要人工审核
│     └─▶ LangGraph StateGraph
│
├─ 长任务、要文件系统、要派子代理、上下文会爆
│     └─▶ Deep Agents create_deep_agent
│
└─ 要生产部署、要可观测性
      └─▶ 以上任一 + LangSmith（追踪/评估/部署）
```

## 4. 同一个需求的三种写法

需求：**查天气并回答**。

### 写法 A：LangChain（最简）

```python
from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    return f"{city} 天气晴朗"

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_weather],
    system_prompt="你是一个乐于助人的助手",
)
agent.invoke({"messages": [{"role": "user", "content": "旧金山天气如何？"}]})
```

### 写法 B：LangGraph（显式图）

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langchain.chat_models import init_chat_model

model = init_chat_model("openai:gpt-5.5").bind_tools([get_weather])

def call_model(state: MessagesState):
    return {"messages": [model.invoke(state["messages"])]}

def should_continue(state: MessagesState):
    last = state["messages"][-1]
    return "tools" if last.tool_calls else END

builder = StateGraph(MessagesState)
builder.add_node("agent", call_model)
builder.add_node("tools", tool_node)
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue, {"tools": "tools", END: END})
builder.add_edge("tools", "agent")
graph = builder.compile()

graph.invoke({"messages": [{"role": "user", "content": "旧金山天气如何？"}]})
```

### 写法 C：Deep Agents（带文件系统与子代理）

```python
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="openai:gpt-5.5",
    tools=[get_weather],
    system_prompt="你是一个研究助手，遇到复杂任务先列计划再执行。",
)
agent.invoke({"messages": [{"role": "user", "content": "调研旧金山未来一周天气并写成报告"}]})
```

差别在于：C 的 Agent 会自己写 TODO、把中间结果落到虚拟文件、必要时派子代理。

## 5. 常见误区

| 误区 | 事实 |
|---|---|
| 「LangGraph 是 LangChain 的一部分，必须一起装」 | LangGraph 可独立使用，只需 `pip install langgraph` |
| 「Deep Agents 是另一个厂商的产品」 | 同一家（LangChain Inc.），且构建在 LangChain 之上 |
| 「用了 Deep Agents 就不能自定义」 | 可以：中间件、后端、权限、子代理全可覆盖 |
| 「create_agent 不能做复杂流程」 | 可以，通过中间件组合；再复杂就下沉到 LangGraph |
| 「LangSmith 是必须的」 | 不是必需，但生产环境强烈建议用于追踪与评估 |

## 6. 迁移路径

```text
create_agent  →  加中间件  →  仍不够  →  下沉到 LangGraph 自定义 StateGraph
                                  ↓
                          需要长任务能力 → 换成 create_deep_agent
```

官方也提供了迁移指南：

- LangChain v1 迁移指南
- LangGraph v1 迁移指南
- 从 `langgraph-supervisor` 迁移到「子代理模式」
- 从 `langchain-mcp-adapters` 迁移到内置 `langchain.mcp`

---

## 7. 版本要点（v1）

- **LangChain v1** 把 `AgentExecutor`/`initialize_agent` 全部收敛到 `create_agent`，旧的 Chain 写法进入维护模式。
- **LangGraph v1** 稳定了 `StateGraph` 与 `@entrypoint` 两套 API，并强调「图 API」与「函数式 API」可按需选择。
- **Deep Agents** 从 v0.7 起，待办清单改为显式开启，文件系统工具可通过 `excluded_tools` / `tools` 白名单裁剪。
