# OpenShift 学习大纲

> 目标：从「会用 kubectl」走到「能独立运维一个 OCP 集群」。
> 建议周期：6 周，每周 6～8 小时。每个阶段都配一个能跑出来的小实验，光看文档记不住。

## 第 0 阶段：先分清它和 Kubernetes 的关系（2～3 小时）

- OpenShift = Kubernetes + 企业级增强（安全、构建、路由、监控、Operator 生态）
- 关键差异点：
  - **Route** vs Ingress：OCP 默认用 Route（HAProxy Router）
  - **SCC**（Security Context Constraints）：比 K8s 的 PSP/PSA 更严格，默认不给 root
  - **ImageStream / BuildConfig**：内置镜像构建流水线，不必自己搭 CI
  - **DeploymentConfig**（老）与 Deployment（新）并存，新项目一律用 Deployment
  - **OperatorHub**：集群能力的安装入口
- 产出：一张自己画的对照表，左边 K8s 概念，右边 OCP 对应物。

## 第 1 阶段：把环境跑起来（1 周）

- 三条路线，按机器条件选：
  - **CRC / OpenShift Local**：单人笔记本最快上手，内置单节点
  - **Single Node OpenShift (SNO)**：一台机器模拟生产形态
  - **正式集群**：IPI（ installer-provisioned，AWS/vSphere/裸机）或 UPI
- 要掌握：
  - `crc start` / `crc console` / `crc oc-env`
  - kubeconfig 在哪、`oc login` 怎么登
  - 集群健康三件套：`oc get nodes`、`oc get clusteroperators`、`oc get clusterversion`
- 实验：本地起 CRC，登录 web console，跑一个 hello world。

## 第 2 阶段：核心对象与日常操作（1～2 周）

- 工作负载：Pod、Deployment、StatefulSet、DaemonSet、Job/CronJob
- 配置：ConfigMap、Secret
- 网络：Service（ClusterIP/NodePort/LoadBalancer）、Route、Headless Service
- 存储：PV、PVC、StorageClass、访问模式（RWO/ROX/RWX）
- 项目与配额：Project、ResourceQuota、LimitRange
- 实验：部署一个有状态应用（比如 PostgreSQL），配 PVC + Service + Route，能被外网访问。

## 第 3 阶段：镜像与构建（1 周）

- ImageStream、ImageStreamTag、imagestream 自动更新触发器
- BuildConfig 四种策略：Source（S2I）、Docker、Pipeline、Custom
- `oc new-app`、`oc start-build`、`oc logs -f bc/xxx`
- 从 Git 直接构建：S2I 与 Dockerfile 两种路径的取舍
- 实验：把自己的一个小项目用 S2I 构建出来，再改成 Dockerfile 构建，比较差异。

## 第 4 阶段：安全与权限（1 周）

- 认证：HTPasswd / LDAP / OIDC 身份提供者
- 授权：Role、ClusterRole、RoleBinding、ClusterRoleBinding、ServiceAccount
- SCC：为什么默认镜像不能跑 root，`anyuid` 什么时候才该给
- 网络策略：NetworkPolicy 默认拒绝、按 namespace 放行
- 实验：建两个项目，A 的 Pod 访问 B 的 Service，先用 NetworkPolicy 拦掉，再精准放行。

## 第 5 阶段：可观测性与运维（1 周）

- 内置监控：Prometheus、Alertmanager、Grafana，`oc get route -n openshift-monitoring`
- 日志：OpenShift Logging（Loki 或 Elasticsearch 方案）
- 事件与审计：`oc get events`、audit log 在哪
- 节点运维：cordon / drain / uncordon，`oc debug node/`
- 备份与升级：etcd 备份、`oc adm upgrade`、升级前检查清单
- 实验：故意让一个 Pod CrashLoopBackOff，用 events + logs + describe 三步定位。

## 第 6 阶段：Operator 与 CI/CD（1 周）

- Operator 是什么：CRD + 控制器 + 运维知识封装
- OLM：Subscription、ClusterServiceVersion、OperatorGroup
- 用 Operator 装一个中间件（比如 Crunchy Postgres 或 Strimzi Kafka）
- 流水线：OpenShift Pipelines（Tekton）、GitOps（Argo CD）
- 实验：用 Argo CD 把本仓库里的一个 Deployment 同步进集群。
