# 路径一：Describe cloud concepts（云概念）

> 考试占比 25～30%。这一部分全是概念，不考动手，但要背准定义与区别。

## 模块 1 云计算基础

### 什么是云计算

通过网络（互联网）按需提供计算资源——计算、存储、网络、数据库、分析、AI 等，按使用量付费，无需自己采购和维护硬件。

**关键特征（五大）**：

| 特征 | 含义 |
| --- | --- |
| 按需自助服务 | 用户自己开通资源，不用走人工审批流程 |
| 广泛网络访问 | 通过公网/专线随时访问 |
| 资源池化 | 服务商把资源池化，多租户共享 |
| 快速弹性 | 需求上来能迅速扩容，需求下去能缩容 |
| 计量付费 | 按实际用量计费（像水电） |

### 为什么企业上云

- **资本支出（CapEx）转运营支出（OpEx）**：不用买服务器，改成按月付费。
- 不用预估容量：传统机房要么买多了闲置，要么买少了不够。
- 全球部署：在需要的地域就近开设资源。
- 更快上线：不用等硬件采购、机房上架。

### 消费模型

- **基于消费（consumption-based）**：用多少付多少。
- **预留实例（Reserved）**：承诺 1～3 年，换更低单价。
- **混合权益（Hybrid Benefit）**：带已有的 Windows Server / SQL Server 许可证，省钱。

## 模块 2 云的优势

### 高可用性与可伸缩性

- **高可用（High availability）**：服务在故障时仍可用，靠冗余与多副本实现，通常用「几个 9」衡量（99.9% = 一年约 8.76 小时不可用）。
- **可伸缩（Scalability）**：能力可以放大或缩小。分两种：
  - **纵向扩展（Vertical / scale up）**：给单台机器加 CPU、内存。
  - **横向扩展（Horizontal / scale out）**：增加机器数量。
- **弹性（Elasticity）**：能根据负载自动伸缩，而且是**双向**的（也可缩容）。

### 可靠性与可预测性

- **可靠性（Reliability）**：系统在故障后能恢复并继续按预期工作，通常靠多区域部署、备份、容灾实现。
- **可预测性（Predictability）**：性能可预测（自动伸缩、负载均衡）+ 成本可预测（定价计算器、预算告警）。

### 安全性与可管理性

- **安全性**：云服务商提供物理安全、网络防护、身份体系；客户负责数据与配置。可用策略、加密、合规工具。
- **可管理性（Manageability）**：
  - 对云资源的管理：自动伸缩、模板部署、监控告警。
  - 对云本身的管理：Web 门户、CLI、API、日志与自动告警。

## 模块 3 云服务类型

### IaaS / PaaS / SaaS

| 类型 | 你管理什么 | 典型例子 | 适用 |
| --- | --- | --- | --- |
| IaaS | 操作系统及以上（OS、运行时、应用、数据） | Azure VM、托管磁盘 | 需要完全控制、迁移老系统 |
| PaaS | 只要管应用和数据 | App Service、Azure SQL、Functions | 专注开发、少管基础设施 |
| SaaS | 只管数据和配置 | Microsoft 365、Dynamics 365 | 直接用现成软件 |

### 责任共担模型（极高频考点）

| 层级 | IaaS | PaaS | 本地机房 |
| --- | --- | --- | --- |
| 数据与访问 | 客户 | 客户 | 客户 |
| 应用 | 客户 | 客户 | 客户 |
| 运行时 | 客户 | 微软 | 客户 |
| 操作系统 | 客户 | 微软 | 客户 |
| 虚拟化 | 微软 | 微软 | 客户 |
| 物理主机/网络/机房 | 微软 | 微软 | 客户 |

**口诀**：越往 SaaS 走，客户管得越少，但**数据、账户、设备永远是客户的**。

### Serverless（无服务器）

- 不需要自己管理服务器，代码按事件触发执行、按执行时长计费。
- 例子：Azure Functions、Logic Apps、Event Grid。
- 不等于「没有服务器」，而是「你不关心服务器」。

## 模块 4 云部署模型

| 模型 | 说明 | 典型场景 |
| --- | --- | --- |
| 公有云 | 资源归云服务商，多租户共享，公网访问 | 大多数互联网业务 |
| 私有云 | 资源专供一个组织，可在本地或托管机房 | 金融、政务、强合规 |
| 混合云 | 公有云 + 私有云并用，数据与身份打通 | 核心数据本地、前端上云 |
| 多云 | 同时用两家以上云厂商 | 避免锁定、灾备 |

### 相关概念

- **Azure Arc**：把本地/其他云的服务器、Kubernetes 纳入 Azure 统一管理。
- **Azure VMware Solution**：把 VMware 工作负载迁移到 Azure。
- **主权云（Sovereign Cloud）**：针对特定国家的合规要求单独部署。

## 本路径高频考点

1. 五种云特征中，「计量付费」和「弹性」最常被考。
2. 纵向扩展 vs 横向扩展的定义区分（scale up / scale out）。
3. 责任共担：SaaS 下客户仍需管理数据与身份。
4. IaaS 需要客户打补丁、管操作系统，PaaS 不需要。
5. 混合云的关键是「数据/身份互通」，不是简单的「有两朵云」。
