# 路径二：Describe Azure architecture and services（架构与服务）

> 考试占比 35～40%，是分量最重的一块，也是名词最多的一块。

## 模块 1 核心架构组件

### 层级结构（从大到小）

```
管理组 Management Group
   └── 订阅 Subscription
          └── 资源组 Resource Group
                 └── 资源 Resource
```

- **管理组**：批量对多个订阅套用策略与权限，最多 6 层。
- **订阅**：计费与配额的边界；一个账户可以有多个订阅。
- **资源组**：资源的逻辑容器，**一个资源只能属于一个资源组**，删组即删资源。
- **资源**：单个服务实例，如一台 VM、一个存储账户。

### 区域与可用性

| 概念 | 说明 |
| --- | --- |
| 区域 Region | 一组数据中心组成的地理区域，如 Japan East |
| 可用性区域 AZ | 同一区域内物理隔离的三个（或更多）数据中心组 |
| 区域对 Region pair | 相距 300 英里以上的成对区域，用于灾备 |
| 主权区域 | 政府/合规专用区域 |

- **SLA 与可用性**：单 VM 99.9%，可用性区域 99.99%，跨区域 99.99%+。
- 选区域看三点：**延迟、合规、服务可用性**（不是所有服务在所有区域都有）。

### 订阅与账号

- 计费账户 → 订阅 → 资源；一个订阅可以关联多个管理员。
- 常见订阅类型：免费账户、按需付费、企业协议（EA）、CSP。

## 模块 2 计算与网络

### 计算服务

| 服务 | 类型 | 说明 |
| --- | --- | --- |
| 虚拟机 VM | IaaS | 完全可控，自己管 OS |
| 虚拟机规模集 VMSS | IaaS | 一组同构 VM，自动伸缩 |
| App Service | PaaS | 托管 Web 应用与 API，支持多语言 |
| Azure Functions | Serverless | 事件驱动，按执行计费 |
| 容器实例 ACI | 容器 | 快速跑单个容器，无需编排 |
| Azure Kubernetes Service AKS | 容器 | 托管 K8s，控制面免费 |
| Azure Container Apps | Serverless 容器 | 基于 KEDA 的自动伸缩 |
| Azure Virtual Desktop | 桌面 | 云上虚拟桌面 |

**选择顺序**：能用 PaaS 就不上 IaaS；需要 K8s 全套能力才用 AKS。

### 网络服务

| 服务 | 作用 |
| --- | --- |
| 虚拟网络 VNet | 隔离的私有网络，划分子网 |
| 网络安全组 NSG | 子网/NIC 级防火墙规则，默认拒绝入站 |
| Azure Load Balancer | 四层负载均衡（TCP/UDP） |
| Application Gateway | 七层负载均衡，带 WAF |
| Azure Front Door | 全球七层入口，CDN + WAF + 加速 |
| VPN Gateway | 站点到站点/点到站点的加密连接 |
| ExpressRoute | 专线连接，不经过公网 |
| Azure DNS | 托管 DNS 区域 |
| Private Endpoint | 把 PaaS 服务私有接入 VNet |
| Azure Bastion | 通过浏览器安全连 VM，不用公网 IP |

**排障顺序**：NSG → 路由表（UDR）→ DNS → 对端配置。

## 模块 3 存储服务

### 四类存储

| 类型 | 用途 |
| --- | --- |
| Blob Storage | 对象存储：图片、视频、备份、日志 |
| Azure Files | SMB/NFS 文件共享，可挂载 |
| Managed Disks | VM 的块存储（磁盘） |
| Queue / Table | 轻量消息与键值（新项目多用 Service Bus / Cosmos DB） |

### Blob 的层次与访问

- 访问层：**Hot / Cool / Cold / Archive**，冷层存储便宜、取回贵且有延迟。
- 三种 blob：Block（块，常规文件）、Append（追加，日志）、Page（页，VHD）。
- 访问方式：公共读、SAS 令牌、Azure AD 身份、私有终结点。

### 冗余选项

| 选项 | 说明 |
| --- | --- |
| LRS | 同一数据中心三副本 |
| ZRS | 跨可用性区域三副本 |
| GRS | 跨区域复制（主区 + 配对区） |
| GZRS | 跨区域 + 区域内多可用区 |
| RA-GRS | GRS + 次要区域可读 |

### 迁移与传输工具

- **AzCopy**：命令行批量拷贝。
- **Storage Explorer**：图形化浏览。
- **Azure Migrate**：评估并迁移本地 VM/数据库/Web 应用。
- **Azure Data Box**：物理硬盘寄送，适合 TB 级海量离线传输。
- **File Sync**：把本地文件服务器与 Azure Files 双向同步。

## 模块 4 身份、访问与安全

### Microsoft Entra ID（原 Azure AD）

- 云身份服务：用户、组、应用注册、设备。
- **SSO**：一次登录访问多个应用。
- **MFA**：多因素认证（密码 + 手机/令牌）。
- **条件访问（Conditional Access）**：按用户、设备、位置、风险决定是否放行。
- **B2B**：邀请外部用户；**B2C**：面向消费者的身份（现为 External ID）。
- **Entra Domain Services**：托管的域服务（LDAP/Kerberos），兼容老应用。

### 授权模型

- **RBAC**：在「范围」上给「主体」分配「角色」。
  - 范围：管理组 → 订阅 → 资源组 → 资源。
  - 角色：Owner、Contributor、Reader，以及大量服务专用角色。
  - 原则：**最小权限**。
- **Azure Policy** 管的是「资源长什么样」，RBAC 管的是「谁能操作」。

### 安全体系

| 服务 | 作用 |
| --- | --- |
| Microsoft Defender for Cloud | 安全态势评估 + 威胁防护（CSPM/CWPP） |
| Azure Key Vault | 存密钥、证书、连接串 |
| Managed Identity | 给资源一个身份，免密钥访问其他服务 |
| Microsoft Sentinel | SIEM/SOAR，安全事件分析 |
| Zero Trust | 永不信任、始终验证：身份、设备、网络、应用、数据 |

### 纵深防御层次

物理安全 → 身份与访问 → 边界（防火墙/DDoS）→ 网络（NSG/分段）→ 计算（补丁/EDR）→ 应用 → 数据（加密/分类）。

## 本路径高频考点

1. 资源只能属于一个资源组；资源组可以跨区域，但资源本身有区域。
2. 可用性区域是「同一区域内物理隔离」，不是「不同区域」。
3. NSG 默认拒绝入站、允许出站；优先级数字越小越优先。
4. Blob 的 Archive 层不能直接读，要先 rehydrate。
5. RBAC 与 Azure Policy 的区别（谁能做 vs 能做成的样子）。
6. 托管标识 vs 服务主体（前者免密码，推荐）。
7. ExpressRoute 不走公网，VPN 走公网加密隧道。
