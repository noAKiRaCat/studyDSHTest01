# 路径三：Describe Azure management and governance（管理与治理）

> 考试占比 30～35%。这一块最容易「看着都会、做题就错」，因为工具名字多、职责边界细。

## 模块 1 成本管理

### 影响成本的因素

- **资源类型**：VM 比存储贵，GPU 比 CPU 贵。
- **用量**：按秒/按小时计费，用得越久越贵。
- **区域**：不同区域单价不同。
- **计费模型**：按需（Pay-as-you-go）、预留（Reserved 1/3 年，省 40%～70%）、现货（Spot，便宜但可能被回收）。
- **网络流量**：出站流量（egress）通常收费，入站免费；跨区域流量收费。
- **订阅类型与混合权益**：EA、CSP、Azure Hybrid Benefit。

### 成本工具

| 工具 | 用途 |
| --- | --- |
| 定价计算器（Pricing Calculator） | **上线前**估算成本 |
| TCO 计算器（Total Cost of Ownership） | 对比「本地机房 vs Azure」的总拥有成本 |
| Microsoft Cost Management | **上线后**看账单、做预算、设告警、做成本分析 |
| 成本告警与预算 | 超过阈值通知，防止账单失控 |

> 记忆点：**Pricing Calculator 算「将来」，Cost Management 看「现在」，TCO 比「本地 vs 云」**。

### 标签（Tags）

- 键值对，用于**成本分摊、自动化、合规**。
- 不继承到子资源（但可以通过策略强制继承）。
- 一个资源最多 50 个标签。
- 标签不用于计费本身，但可以按标签做成本归集。

## 模块 2 治理与合规

### Azure Policy

- 定义「资源必须长什么样」：允许的区域、必须有标签、禁止某些 SKU。
- 效果：`Deny`（拒绝创建）、`Audit`（只记录）、`Append`（补字段）、`DeployIfNotExists`（自动补齐）。
- **合规性仪表盘**能看到整体达标率。
- Policy 与 RBAC 的区别：**Policy 管资源形态，RBAC 管人的权限**。

### Azure Blueprints（蓝图）

- 把「策略 + 角色分配 + ARM 模板 + 资源组」打包成可重复部署的模板。
- 新订阅可以一键套用标准配置。
- 现在微软更推荐用 **Template Specs + Deployment Stacks**，但 AZ-900 只考蓝图概念。

### 资源锁（Resource Locks）

| 锁类型 | 效果 |
| --- | --- |
| CanNotDelete（Delete） | 可读写，不能删 |
| ReadOnly | 只读，不能改也不能删 |

- 锁**不继承**到子资源？——实际上会继承到子资源（父级锁作用于子资源），但子资源可以加更严格的锁。
- 锁优先于 RBAC：即使是 Owner 也删不掉被锁定的资源。

### 合规与信任

- **Microsoft 信任中心（Trust Center）**：合规报告、隐私声明、审计文档。
- **Service Trust Portal**：下载审计报告与合规证书。
- **Microsoft Purview**：数据治理、数据地图、敏感信息分类。
- **主权云 / 数据驻留**：某些国家对数据存放地有硬性要求。

## 模块 3 管理与部署工具

### 交互方式

| 工具 | 特点 |
| --- | --- |
| Azure Portal | 图形界面，适合学习与临时操作 |
| Azure CLI（`az`） | 跨平台命令行，脚本化 |
| Azure PowerShell（`Az`） | Windows 生态友好 |
| Cloud Shell | 浏览器里的免费 shell，自带 CLI 与存储 |
| Azure Mobile App | 手机上看资源与告警 |
| REST API / SDK | 程序化集成 |

### 基础设施即代码

- **ARM 模板**：JSON 描述资源，声明式，可重复部署。
- **Bicep**：ARM 的简洁 DSL，编译成 ARM，**新项目首选**。
- **Terraform**：跨云方案（非微软官方，但广泛使用）。
- **部署模式**：
  - **增量（Incremental）**：只增改，不删除模板外的资源（默认）。
  - **完整（Complete）**：模板外的资源会被删除（慎用）。

### 混合与多云管理

- **Azure Arc**：把本地/其他云的服务器、K8s、数据库纳入 Azure 管理。
- **Azure Update Manager**：统一打补丁。
- **Azure Automation**：Runbook 自动化、配置管理。

## 模块 4 监控工具

| 工具 | 作用 |
| --- | --- |
| Azure Monitor | 统一平台：指标（Metrics）+ 日志（Logs） |
| Log Analytics | 日志存储与 KQL 查询 |
| Application Insights | 应用性能监控（APM）：请求、依赖、异常 |
| Azure Monitor Alerts | 告警规则 + 动作组（邮件、短信、Webhook） |
| Service Health | 微软侧的服务中断、计划维护、健康公告 |
| Resource Health | 你名下具体资源的健康状态 |
| Azure Advisor | 最佳实践建议：成本、安全、可靠性、性能、卓越运营 |
| Network Watcher | 网络诊断：连接测试、流日志、拓扑 |

### 区分三个「健康」

- **Service Health**：Azure 整体/区域服务是否正常（微软的问题）。
- **Resource Health**：你这个资源是否正常（可能是平台也可能是你配置的问题）。
- **Azure Status**：全球范围的公开故障公告页。

### 三条告警信号

- **指标告警**：CPU > 80% 持续 5 分钟。
- **日志告警**：KQL 查询命中特定错误。
- **活动日志告警**：谁删了资源、谁改了配置。

## 本路径高频考点

1. Pricing Calculator（预估）vs TCO（本地对比）vs Cost Management（实际账单）。
2. 资源锁优先于 RBAC：Owner 也删不掉。
3. Policy 效果里 `Deny` 与 `Audit` 的区别；`DeployIfNotExists` 会自动补。
4. 增量部署是默认，完整部署会删模板外资源。
5. Service Health（平台）vs Resource Health（资源）。
6. Advisor 给建议，不自动修复。
7. 标签不继承，但可以用 Policy 强制。
